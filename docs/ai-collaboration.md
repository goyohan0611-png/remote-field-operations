# 개발과 검증 과정

## 개발 방식

AI 코딩 도구를 이용해 프로토타입 구현과 디버깅을 진행했습니다. 요구사항을 한 번 입력해 제품을 완성한 것이 아니라, 실제 현장 제약과 시험 결과를 반복적으로 제공하면서 설계를 구체화했습니다.

| 단계 | 직접 담당한 일 | AI를 활용한 일 |
| --- | --- | --- |
| 문제 정의 | 현장 관리의 불편과 장애 상황 정리 | 문제를 기능·예외 상황으로 분해 |
| 설계 | 도입 범위와 우선순위 결정, 접근 방식 선택 | 구성안 비교, 연결 구조·인터페이스 정리 |
| 구현 | 요구사항 구체화, 동작 확인, 수정 방향 판단 | UI·서버·에이전트 코드 작성 보조 |
| 디버깅 | 실제 오류·로그·네트워크 상태 제공 | 원인 후보 분석, 수정안·검증 방법 제안 |
| 검증 | 장비 연결과 현장 동작 시험, 결과 피드백 | 단위 테스트·정적 검사·회귀 점검 보조 |
| 전달 | 기능과 제약 설명, 개발팀 인계 범위 정리 | 문서·구조도·시연 자료 정리 보조 |

## 개발 과정에서 중점을 둔 부분

- 기존 장비와 프로그램을 유지하면서 별도 연결·관리 계층을 추가했습니다.
- 네트워크·OS·구형 앱의 제약을 확인하고 문제별 대안을 선택했습니다.
- AI가 제안한 변경은 실제 환경의 시험 결과를 바탕으로 다시 검토했습니다.
- 구현 기능과 시험 결과, 한계와 향후 아이디어를 구분해 기록했습니다.

## 과장하지 않는 범위

- AI 도움 없이 모든 코드를 직접 작성했다고 표현하지 않습니다.
- Tailscale·SSH·RDP·FTP 자체를 개발했다고 표현하지 않습니다.
- 기존 제조사 소프트웨어나 이후 개발팀의 웹 제품을 본인 개발물로 표현하지 않습니다.
- 구조를 이해하고 통합한 기여와 기반 도구가 제공하는 기능을 구분합니다.
- 측정 근거 없는 비용·장애율·응답 시간 개선 수치를 사용하지 않습니다.

이 저장소에는 기존 UI와 선별한 서버·에이전트 핵심 구현을 식별정보 제거 후 포함했습니다. 데모 저장소·로컬 서버·가상 에이전트 실행부는 공개 설명용으로 별도 구성했습니다. 운영 제품 전체의 배포본은 아닙니다.
